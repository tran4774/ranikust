# rnk-ignore

> **Status:** skeleton · **Phase:** 1 ·
> **Depends on:** — (pure data) · **Used by:** `rnk-builder` (`rnk-context`, `rnk-cache` [open: Q-028]) · **Path:** `crates/rnk-ignore/`

**TL;DR:** A port of moby `patternmatcher` v0.6.1: is this context path
excluded by `.dockerignore`? Semantics are `MatchesOrParentMatches` (BuildKit,
docker CLI): not gitignore, and not kaniko's deprecated `Matches`.

## Owns

- Parsing `.dockerignore` contents (BOM, comments, trimming, `Clean`, leading
  `/`), as `ignorefile.ReadAll` does.
- Deciding whether a context path is excluded, with exactly patternmatcher's
  semantics: pattern syntax, `!` exceptions and parent-directory matches.

## Must not

- Read or walk the filesystem: callers walk and ask (`rnk-context`,
  `rnk-builder`).
- Approximate: any divergence from `patternmatcher` is a bug; no `ignore` or
  `globset` crate underneath.
- Choose the ignore file (`<Dockerfile>.dockerignore` before `.dockerignore`):
  `rnk-context` does.

## API (planned)

```rust
pub fn read_patterns(contents: &[u8]) -> Result<Vec<String>, Error>;   // [decided] ignorefile.ReadAll, ADR-0015
pub struct Matcher { /* compiled patterns, has_exclusions */ }          // [decided] port of PatternMatcher
impl Matcher {
    pub fn new(patterns: &[String]) -> Result<Matcher, Error>;          // [design] compiles eagerly: matching cannot fail
    pub fn matches_or_parent_matches(&self, path: &str) -> bool;        // [decided] BuildKit's call
    pub fn matches_using_parent(&self, path: &str, parent: &MatchInfo) -> (bool, MatchInfo); // [design] for walks
    pub fn has_exclusions(&self) -> bool;  // [design] false => a walk may skip an excluded directory
}   // [open: Q-010] path type: &str, or bytes (regex::bytes) for non-UTF-8 names
```

## Invariants

- Same answer as `PatternMatcher.MatchesOrParentMatches` v0.6.1 for every
  (patterns, path) pair.
- No panic on any pattern or path; no I/O; no state between calls.
- Paths are relative, `/`-separated and cleaned; `.` (the context root) is
  never excluded (kaniko `fs_util.go:1236-1239` does the same).

## Tests

- T0 golden: exp-04's 38 pattern cases × 42 paths (1,596 cells), generated by
  a Go program calling `MatchesOrParentMatches`, committed; plus the cases of
  upstream `patternmatcher_test.go`.
- T0 property: no panic on random input; `p` then `!p` re-includes; `./a`
  equals `a`; `matches_using_parent` along a walk equals
  `matches_or_parent_matches`. Compatibility: kaniko's
  `Dockerfile_test_dockerignore`, `Dockerfile_dockerignore_relative`.

## Metrics

- None: matching is per path, so a span would be per file. Its cost is
  charged to `rnk_context.ignore` ([rows](../../design/metrics.md#rnk-ignore)).
- No `tracing` dependency needed.

## Pitfalls

- gitignore is not dockerignore: a pattern without `/` matches only at the
  root, so `*.txt` keeps `sub/a.txt` ([exp-04](../../research/experiments/04-dockerfile-parser.md#dockerignore)).
- `*/` cleans to `*` and also matches files; `!*/` after `*` becomes `!*` and
  re-includes everything (exp-04).
- A child can be re-included below an excluded parent (`docs` +
  `!docs/keep.md`, `*` + `!foo/bar`): a walker must not prune excluded
  directories while exclusions exist (exp-04).
- `[!b]` is a class containing `!`; only `[^b]` negates (exp-04).
- `ReadAll` tests for `#` before trimming (an indented `#` is a pattern),
  strips a BOM on the first line only, then cleans and drops one leading `/`
  ([ignorefile.go](https://github.com/moby/patternmatcher/blob/v0.6.1/ignorefile/ignorefile.go#L37)).
- A lone `!` is an error, and syntax is validated like Go's
  `filepath.Match` ([patternmatcher.go](https://github.com/moby/patternmatcher/blob/v0.6.1/patternmatcher.go#L54)).
- kaniko's `Matches` does not exclude `foo/a.txt` for `**/foo`
  (`fs_util.go:1241`); ranikust follows BuildKit (ADR-0015).
- Go `regexp` and Rust `regex` differ in details: port `compile` literally and
  test escapes (`\*`, `[`, `.+()|{}$`) [inferred].
